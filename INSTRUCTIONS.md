OPCIÓN 3
Sistema de Organización Académica con Recorridos Estructurados
1. Descripción del proyecto
El grupo desarrollará un sistema académico que gestione materias, estudiantes, tareas, evaluaciones o recursos de estudio. La particularidad del proyecto será que la información no solo se almacenará, sino que se organizará mediante estructuras de datos adecuadas para representar relaciones jerárquicas y procesos de atención.
Este proyecto permite trabajar estructuras lineales y no lineales dentro de un contexto cercano al entorno universitario.
2. Objetivo general
Desarrollar un sistema académico que incorpore estructuras de datos para modelar relaciones jerárquicas, secuencias de atención y administración eficiente de registros.

3. Estructuras de datos que deben aplicarse dentro del proyecto
Este proyecto deberá incorporar obligatoriamente:
•	TAD para Estudiante, Materia, Tarea o Recurso.
•	Pila para historial de navegación o acciones recientes.
•	Cola para tareas pendientes o solicitudes de revisión.
•	Lista enlazada para gestionar conjuntos dinámicos de estudiantes o tareas.
•	Árbol o árbol binario de búsqueda para representar organización jerárquica de contenidos, materias o búsqueda por códigos.
•	Breve análisis de complejidad en operaciones de inserción, recorrido o consulta.
4. Funcionalidades obligatorias
•	Registrar estudiantes.   – ADMINISTRADOR - CORDINADORA
•	Registrar materias o tareas. 
•	Agregar tareas pendientes.
•	Gestionar solicitudes en espera.
•	Consultar historial de acciones.
•	Organizar información mediante una estructura jerárquica.
•	Recorrer y mostrar árboles.
•	Buscar elementos dentro de una estructura no lineal.

5. Extras
•	Calendario académico.
•	Clasificación por prioridad.
•	Árbol por unidades o temas.
•	Simulador de prerrequisitos.
•	Reportes y estadísticas.

REQUISITOS OBLIGATORIOS PARA TODOS LOS PROYECTOS
Independientemente del tema elegido, todos los grupos deberán cumplir obligatoriamente con lo siguiente:
1. Enfoque académico obligatorio
El proyecto debe evidenciar el uso de los contenidos centrales de la asignatura:
•	abstracción,
•	tipos abstractos de datos,
•	modelado con características orientadas a objetos de Python,
•	complejidad algorítmica,
•	pilas,
•	colas y sus variantes,
•	listas enlazadas simples, dobles o circulares,
•	árboles y árboles binarios de búsqueda  


2. Requisitos técnicos mínimos
Todo proyecto deberá incluir:
•	clases para representar entidades principales;
•	implementación de al menos un TAD propio;
•	uso de al menos una pila;
•	uso de al menos una cola o cola de prioridad;
•	uso de al menos una lista enlazada;
•	uso de al menos un árbol o árbol binario de búsqueda;
•	operaciones de inserción, eliminación, búsqueda y recorrido;
•	explicación del porqué se usó cada estructura;
•	comparación básica de eficiencia entre dos soluciones o estructuras.

3. Restricción importante
No se aceptará un proyecto que simplemente almacene todo en listas de Python sin justificar estructuras.
La nota no dependerá solo de que “funcione”, sino de que el sistema demuestre claramente la aplicación real de estructuras de datos.

4. Sustento conceptual obligatorio
Cada grupo deberá poder explicar:
•	qué estructura utilizó,
•	por qué la eligió,
•	qué operación resuelve,
•	qué ventajas ofrece,
•	y qué complejidad aproximada tiene en sus operaciones principales
